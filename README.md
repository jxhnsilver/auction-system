# Auction System

## Описание
**Auction System** - это backend-сервис для управления онлайн-аукционами. Платформа предоставляет REST API для регистрации пользователей, создания лотов, управления торгами и совершения ставок в режиме реального времени.

Проект построен с акцентом на надёжность, консистентность данных и масштабируемость. Архитектура поддерживает конкурентные ставки с защитой от гонок (race conditions), автоматизированное жизненный цикл аукционов и встроенную систему холдирования средств для оптимизации взаимодействия с платёжными шлюзами.

## Запуск
1. Склонируйте репозиторий и перейдите в корневую директорию:
   ```bash
   git clone https://github.com/jxhnsilver/auction-system.git
   ```
2. Скопируйте файл конфигурации окружения и заполните его необходимыми данными:
   ```bash
   cp .env.example .env
   ```
3. Соберите образы и запустите контейнеры в `Docker`:
   ```bash
   docker compose up --build
   ```
4. Откройте интерфейсы:
   - API (Swagger): http://localhost:8080/swagger

## Функционал
### Реализованные возможности
- **Аутентификация и авторизация**  
    - Регистрация и вход пользователей с выдачей JWT-токенов
    - Защищённые эндпоинты с валидацией токенов
- **Система ставок с защитой от гонок**
    - Для корректной обработки конкурентных ставок применяется **пессимистическая блокировка** (pessimistic locking), которая выстраивает запросы в очередь, предотвращая конфликты транзакций и избыточные повторные попытки, свойственные оптимистической блокировке
    - Все операции со ставками выполняются **транзакционно** через `BeginTransactionAsync`
- **Автоматизация жизненного цикла аукционов**
    - **Worker #1**: Фоновый сервис для автоматического открытия запланированных аукционов по достижению указанной даты и времени
    - **Worker #2**: Фоновый сервис для автоматического закрытия истёкших аукционов
- **Система кошельков и холдов**
    - Встроенная логика пользовательских кошельков с полями `Balance` и `LockedBalance`
    - При совершении ставки средства замораживаются (холдируются) на кошельке
    - При перебивании ставки - средства автоматически размораживаются
    - Таблица `wallet_holds` хранит полную историю операций холдирования
    - Оптимизация производительности за счёт избежания лишних запросов к платёжным системам.
- **Обработка ошибок**
    - Единый **Result Pattern** вместо исключений в бизнес-логике.
    - Унифицированный формат ответов об ошибках через **Problem Details** (RFC 7807).
- **Покрытие тестами**  
    - Доменный слой покрыт unit-тестами (xUnit), включая проверку бизнес-логики основных агрегатов и их сущностей.
